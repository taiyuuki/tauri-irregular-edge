# tauri-irregular-edge

验证 Tauri 2 的透明窗口能不能做出输入法皮肤那样的效果：不规则轮廓、半透明图片、九宫格拉伸，
以及轮廓之外的区域能不能点击穿透。

验证环境：macOS 27.2.1（Apple Silicon），Tauri 2.12.7（tao 0.37.3、wry 0.57.4），主显示器 1920×1080、缩放 1x。
只在 macOS 上验证过，Windows 和 Linux 没有测。

## 结论

- **不规则轮廓可行。** 屏幕上的像素和“皮肤图叠在背后窗口上”的理论值逐像素吻合，本体、阴影、抗锯齿边缘的最大误差是 0–1/255。
- **九宫格拉伸可行。** 窗口从 349 拉高到 469 逻辑像素后，圆角、缺口、尾巴都保持原样。
- **点击穿透能做，但 Tauri 没有内置，要自己实现，而且有一个 10–20 毫秒的时间窗。**
  光标越过轮廓之后这么快之内点击，点击会被面板的透明部分吃掉，或者凭空丢失。

## 运行

```sh
pnpm install
pnpm tauri dev                          # 开发模式，屏幕中央弹出一个异形面板
pnpm tauri build --debug --no-bundle    # 只编译，产物给下面两个脚本用

scripts/verify.sh                       # 一键验证：像素检查 + 点击穿透
scripts/race-window.sh                  # 单独测点击穿透的时间窗（需要 python3）
```

两个脚本都会临时启动面板和一个独立的原生棋盘格窗口，运行期间会移动鼠标、模拟点击，结束时自动关闭。
`IRREGULAR_HIT_MODE=js scripts/verify.sh` 可以换成“由前端调回去切换穿透”的做法来对比。

## 验证方法和结果

| 验证项 | 怎么测 | 结果 |
| --- | --- | --- |
| 不规则轮廓 | 截取面板矩形范围内的屏幕，和“面板窗口截图 × 背后棋盘格”的理论合成值逐像素比较 | 轮廓之外的 42325 个像素就是纯黑或纯白的棋盘格，最大误差 1/255 |
| 半透明本体 | 同上；再用棋盘格透过本体后剩下的对比度反推不透明度 | 本体 alpha 199（设计值 199）；反推不透明度 0.78（设计值 0.78）；本体内部最大误差 0/255 |
| 柔和阴影 | 面板窗口自身截图的 alpha 通道 | 本体下方阴影 alpha 峰值 88、尾巴两侧 88，逐级渐变；屏幕上最大误差 1/255 |
| 九宫格拉伸 | 点三次“+ 一行”把窗口拉高到 469，重新截屏比对 | 同样全部通过 |
| 停稳后点击穿透 | 光标停 300ms 后点击左上角、本体下方阴影、右侧缺口、右上圆角外 | 4 次全部落到背后另一个进程的窗口 |
| 越界后立刻点击 | 甩到透明处后不到 1ms 按下，三个目标点各 10 次 | 30 次全部被面板吃掉 |
| 时间窗 | 到达后等 N 毫秒再按下，每个 N 做 6–10 次 | 等 0–3ms 全部失败；11–19ms 大部分成功，偶尔失败；20ms 以上没有再失败 |

## 过程中发现的坑

**1. 皮肤图里有三个不同的“边距”，别混用。** 透明边距（36）是皮肤图四周留给阴影的；
九宫格切片（92 / 56 / 66 / 66）等于边距加上这个方向上必须保持原样的部分；
内容区的内边距要让开边距和本体之外的部分（底部的尾巴）。我把内容区按切片值写了两次，
结果搜索框和按钮画到了轮廓外面。

**2. 点击穿透有一个时间窗。** 做法是轮询光标位置，在轮廓外时让窗口忽略鼠标事件。
从光标越界到切换生效需要几毫秒（Rust 线程里直接切换是 0–8ms，偶有 30ms 的长尾；
由前端调回去切换是 2–41ms），这期间落下的点击会被面板的透明部分吃掉。

**3. 切换瞬间附近，点击会凭空丢失。** 102 次甩动里有 11–13 次，面板和背后的窗口都没收到点击。
这些点击都落在“面板开始穿透”的前后几毫秒之内。原因没有查清。

**4. 面板不是焦点窗口时，第一次点击只是让它拿回焦点。** 这是 WKWebView 的默认行为
（Safari 的背景窗口也一样）。启动器唤出面板时要主动把焦点给它，否则用户的第一下点击会没反应。

**5. 测点击穿透时，背后的窗口要放在另一个进程里。** 我最初把棋盘格做成同一个应用里的第二个窗口，
两个窗口轮流成为焦点窗口，每次切换焦点的第一次点击都被上面第 4 条吞掉，看起来像是点击被丢了。

## 没有验证的

- Windows 和 Linux。
- Retina（2x）屏幕上的表现。
- 毛玻璃之类的原生窗口效果，以及它和异形皮肤能不能叠在一起。
- 隐藏后再显示、首帧是否闪一下。这里窗口只显示一次。
- release 打包后的表现。验证用的是 debug 构建。

## 对正式项目的建议（没有验证）

轮询切换的做法对自用的启动器大概够用：时间窗只有十几毫秒，人一般不会在光标越过轮廓后这么快点击。
如果想彻底消除时间窗，应该改用各平台原生的“输入区域”机制，让系统在派发点击的那一刻就按像素判断归属：

- macOS：重写内容视图的 `hitTest:`，透明处返回 nil
- Windows：处理 `WM_NCHITTEST`，透明处返回 `HTTRANSPARENT`
- Linux：给窗口设置输入形状区域

这些都需要写少量平台相关的原生代码，这个项目里没有做。
